# 项目初始化：写出 AGENTS.md（等价 opencode /init）

目标：在项目根产出一份**只含可验证事实**的 `AGENTS.md`，服务三类读者——以后的人和 agent（怎么构建/运行/测试）、本 skill 的阶段 3（取证索引）、图集 CI。写事实、留出处，不写愿景。

## 扫描顺序（由广到深，缺什么跳过什么）

1. **自述**：`README*`、docs 首页——项目目的、技术栈、启动方式（有就引用，没有不编）
2. **清单与配置**：`package.json`（scripts/deps）、`pyproject.toml`/`requirements*.txt`、`go.mod`、`pom.xml`/`build.gradle`、`Cargo.toml`、`composer.json`、`docker-compose.yml`、`Dockerfile`、`Makefile`——命令和依赖的权威来源
3. **目录骨架**：顶层 + 二级目录一览；每个目录的职责从命名和文件构成推断，拿不准就不标
4. **入口与路由**：启动文件（`main.*`/`server.*`/`app.*`/`index.*`）、HTTP 路由注册处、CLI 命令定义处——这些同时是阶段 3 的主证据源
5. **数据与消息**：schema/迁移目录、ORM 模型、消息主题/队列声明
6. **测试与工具链**：测试目录与运行命令、lint/格式化配置

## 写作规范

- 只写读得到的事实，关键结论括注来源路径（如「dev：`npm run dev`（package.json）」）
- 建议结构（≤120 行）：
  1. `# <项目名>` + 一句话定位
  2. `## 是什么` / `## 技术栈`（版本来自清单文件）
  3. `## 常用命令`（build/dev/test/lint，标来源）
  4. `## 目录结构`（树 + 每目录一行注释）
  5. `## 关键约定`（分层/命名/错误处理——代码里能看出来的）
  6. `## 已知的坑`（仅当代码有明确证据）
- 语言：README 是中文就写中文，否则跟随代码注释主语言
- 推断要么标注「疑似 X，待确认」，要么不写；禁止把推测写成事实
- 空项目/纯文档目录：如实告知用户没有可出图的代码，不要为了走流程生成空洞的 AGENTS.md

## 边界

- 已存在 `AGENTS.md`：本流程整体跳过（阶段 0 已判断）；只有用户明确说「更新 AGENTS.md」才增补
- `AGENTS.md` 是说明书不是图的替代品，不要把图 spec 塞进去
- 生成的文件属于用户的项目：只新增这一个文件，不改其他任何代码

## 完成标志

文件落在项目根；向用户报告一句：「已生成 AGENTS.md（N 行），主要依据：…」。
